# EstateOS™ — stan prac i jak kontynuować (31.10.2026)

## Gdzie jesteśmy
- Web: gałąź `recovery-local-snapshot`. Wszystko zacommitowane lokalnie, **niewypchnięte** od `522c01c9` (ostatni push).
- Przed deployem: wypchnąć gałąź, potem deploy serwera (polecenia niżej). Deploy robi właściciel — Claude podaje tylko polecenia.
- Nowa migracja SQL: `prisma/manual/sql/2026-10-31_smart_agent_team_log.sql` (skrypt `db:smart-agent`, już w łańcuchu `deploy:server-only` i `deploy:prod`).
  Dodaje: `AgencyCompany.smartAgentUserId`, tabele `SmartAgentSeat` i `AgencyTeamEvent`. Bez niej Smart Agent OS™ działa tylko w trybie zablokowanym, a dziennik zespołu pokazuje tylko aktywności z kart klientów.

## Zrobione w tej sesji (najważniejsze)
- Kredyty: zamrażają się po końcu okresu (pula biura i u agentów), odmrażają przy przedłużeniu; przekazanie z zamrożonej puli zablokowane.
- Cennik: Partner Free (0 zł) tylko na start; Partner Enterprise = do 25 agentów + 1 stanowisko Smart Agent OS™ (wyróżniony opis).
- Lejek transakcji (`src/components/crm/pro/CrmDealsPro.tsx`): wszystkie kolumny na ekranie, responsywny (tablet przewijanie, telefon zakładki etapów),
  filtr Wszyscy / Agent poszukiwań / Pozyskani, „Dlaczego tutaj” na karcie.
- Okno transakcji (`CrmDealSheet.tsx`): wyjaśnienie sytuacji + kroki (najpierw kupujący albo właściciel), wizytówki, podgląd oferty,
  nawigacja w jednym oknie z „Wstecz” i „Pełny widok”, zamknięcie z potwierdzeniem i „Przywróć do lejka”.
- Logika lejka (`src/lib/crm/offerBuyerDeals.ts`): z radaru do lejka tylko po reakcji (wg ustawień Smart Agent), `entry`, `guide`, wiadomości z Dealroomu.
- Smart Agent OS™ (`src/lib/crm/smartAgent.ts`, `/api/crm/smart-agent`, `CrmSmartAgent.tsx`, zakładka „Smart Agent OS™”):
  dostęp = stanowisko z Enterprise (domyślnie kierownik, może przenieść) albo 5 kredytów / 30 dni; ustawienia reakcji (Chcę obejrzeć / Do przemyślenia / ulubione);
  kolumna w lejku z kablem (odłączony iskrzy), pasek życia z odliczaniem.
- Dziennik zespołu (`src/lib/crm/teamLog.ts`, `/api/crm/team-log`, `CrmTeamLog.tsx`, zakładka „Dziennik zespołu”):
  akcje z `/api/crm/offer-buyers` i `/api/crm/clients/[id]` zapisują się automatycznie (`withTeamLog`), plus przelewy kredytów i Smart Agent.
  Kierownik widzi cały zespół dzień po dniu, agent tylko siebie.
- W CRM daty akcji zawsze z godziną i minutą (`stamp()` w `components/crm/pro/format.ts`).

## Do sprawdzenia / dokończenia
1. Po deployu (z migracją): przetestować Smart Agent OS™ — włączenie za 5 kredytów, pasek życia, przeniesienie stanowiska przez kierownika, ustawienia reakcji.
2. Dziennik zespołu: obejrzeć widok po deployu na prawdziwych danych; ewentualnie dopisać logowanie kolejnych akcji (publikacja/edycja ogłoszeń, kalendarz).
3. Okno transakcji: negocjacje, rezerwacja i dokumenty wciąż tylko w pełnej karcie klienta — do przeniesienia do okna.
4. Pomysł odłożony: osobny licznik „kredyty od biura” u agenta (kredyty kupione samemu bezterminowe) — właściciel na razie zostawił jak jest.
5. Aplikacja mobilna: ostatni push `7d2e64c3`; build: `cd ~/eos-mobile-canonical && npm run eas:ios:all`.

## Polecenia (wklejać w terminal na Macu)
Podgląd lokalny: `cd ~/estateos-recovery-deploy && .claude-deploy/dev.sh` (uruchamia też migracje SQL i `next dev` na :3000).

Deploy serwera (po wypchnięciu gałęzi):
```
cd ~/estateos-recovery-deploy && .claude-deploy/run.sh "cd ~/estateos && git pull -q origin recovery-local-snapshot && git log -1 --oneline && (setsid nohup sh -c 'npm run deploy:server-only' > ~/deploy.log 2>&1 < /dev/null &) ; echo DEPLOY_START"
```
```
cd ~/estateos-recovery-deploy && .claude-deploy/run.sh "tail -n 20 -f ~/deploy.log | sed -u '/dump.pm2\|nie powiódł się\|npm ERR/q'"
```
